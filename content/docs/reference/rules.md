Rules are the transforms coldluau applies to each output file. They live in the `[rules]` table of `coldluau.toml`.

**Every darklua rule name is accepted.** A `.darklua.json` rule list ports over unchanged, no renaming and no guessing. What differs is what happens next:

- Names implemented today run
- Names not implemented yet fail at load time naming their milestone, ex: `remove_types is not implemented yet (lands in M2)`
- Names that live somewhere else in coldluau tell you where, ex: `convert_require` points you at the `[requires]` table

Nothing is silently ignored, which is the same policy the rest of [configuration](/docs/reference/configuration) follows. A rule list that loads is a rule list that ran.

## Shipped today

Three rules are coldluau's own, one is darklua parity.

### `const_requires`

coldluau only. darklua has no rule that emits Luau `const` at all, its `make_assignment_local` goes the other way.

```toml
[rules]
const_requires = true
```

Before:

```luau
local Signal = require("./signal")
local Promise = require("@pkg/promise")
```

After:

```luau
const Signal = require("./signal")
const Promise = require("@pkg/promise")
```

#### Conservative skips

The rule deliberately leaves two shapes alone.

Multi bindings are skipped:

```luau
local a, b = require("./a"), require("./b")
```

Annotated locals are skipped:

```luau
local x: Foo = require("./foo")
```

Both stay `local`. The reason is that `const_requires` is a token level rule today, and a token level rule cannot tell those apart from cases where the rewrite would be wrong. Skipping is the safe answer: a missed `const` is a smaller problem than a broken file. The rule becomes exact once the AST rule engine lands.

### `remove_comments`

Accepts `true`, or a table with `except` regexes.

```toml
[rules]
remove_comments = { except = ["^--!"] }
```

Before:

```luau
--!strict
-- a helper module
--[[
  multi line notes
]]
local function add(a: number, b: number): number
	return a + b -- inline note
end
```

After:

```luau
--!strict



local function add(a: number, b: number): number
	return a + b
end
```

#### The important difference from darklua

The default `except` is `["^--!"]`, so Luau directives like `--!strict`, `--!nonstrict`, and `--!native` survive.

**darklua removes them.** That silently changes how your code runs, because a file that was strict mode is suddenly not. coldluau's default protects the directives. If you want darklua's exact behavior, ask for it:

```toml
[rules]
remove_comments = { except = [] }
```

`except` entries are regexes matched against the comment text, so `["^--!"]` is what keeps the directive family and nothing else.

#### Line counts are preserved

A removed comment leaves its newlines behind. A stripped three line block comment becomes three blank lines, not zero, so line numbers stay stable between source and output. Stack traces and error messages from the running game still point at the right line in your `src` tree.

### `add_luau_directive`

coldluau only.

```toml
[rules]
add_luau_directive = "strict"
```

Writes `--!strict` at the top of every output file.

Before:

```luau
local module = {}
return module
```

After:

```luau
--!strict
local module = {}
return module
```

Two conflict rules:

- An existing directive of the **same family** wins. A file that already says `--!nonstrict` is left alone, coldluau does not fight the author
- An **unrelated** directive does not block it. A file starting with `--!native` still gets `--!strict` added

Combine this with `remove_comments` and the default `except` matters: without `["^--!"]` protecting them, the directive this rule adds could be stripped by the other rule.

### `append_text_comment`

darklua parity, same options.

```toml
[rules.append_text_comment]
text = "generated by coldluau, do not edit"   # or file = "header.txt"
location = "start"                            # or "end"
```

| option | values | meaning |
|---|---|---|
| `text` | any string | the comment body |
| `file` | a path | read the body from a file instead |
| `location` | `start`, `end` | which end of the file to append to |

Before:

```luau
return {
	version = "1.0.0",
}
```

After, with `location = "start"`:

```luau
-- generated by coldluau, do not edit
return {
	version = "1.0.0",
}
```

Use `text` or `file`, not both. `file` is the better option for a multi line license header you already keep under version control.

## darklua rules that are not rules here

Three darklua rules have no coldluau rule name, because coldluau models the same capability somewhere better.

| darklua rule | where it lives in coldluau |
|---|---|
| `convert_require` | the `[requires]` table, richer than the rule |
| `inject_global_value` | `[defines]`, **planned (M2)** |
| `remove_spaces` | `generator = "dense"`, **planned (M2)** |

`convert_require` is the interesting one. In darklua it is a rule; in coldluau require rewriting is not optional and not a rule, it is the core of what the tool does, configured through [require targets](/docs/concepts/require-targets) and validated against [realms and clones](/docs/concepts/realms-and-clones).

Using any of these three names in `[rules]` errors with a message pointing at the replacement, so you do not have to come back to this table to find out where it went.
